# Повний офлайн-набір 0.6

Повні нативні пакети GitHub містять програму, Qwen3 0.6B Q8 (639 446 688
байтів), довідник і оглядову карту світу. Модель не потрібно шукати окремо:
після першого запуску програма сама підготує її без мережі, частинами до 8 MiB.
На головній і в офлайн-наборі видно прогрес. Стан «Набір установлено» означає,
що базові файли готові. З першим запитом модель автоматично запускається в RAM.

| Компонент | Підготовка | Межі |
| --- | --- | --- |
| Карта світу | Вбудована, SHA-256 перевіряється | Natural Earth, оглядова геометрія без вулиць/адрес |
| Довідник AMID | Імпорт при створенні/оновленні SQLite | Короткі матеріали AMID, не вся Wikipedia |
| Qwen3 0.6B Q8 | Повна збірка готує сама; легка — одна кнопка завантаження | CPU, контекст 2048; швидкість/RAM залежать від пристрою |
| Власні регіони й моделі | Імпорт MBTiles або GGUF | Детальних карт вулиць у базовому наборі немає |
| Годинники | Шість карток і локальний чеклист уже в мініпрограмі | Без GGUF, MBTiles і телефонної синхронізації |
| Web/PWA | Вбудовані матеріали/карта та окремий кеш | Без нативних GGUF, BLE та MBTiles |

Для завантаження, розпакування й підготовки повного пакета бажано близько
2 GB вільного місця. Після встановлення потрібна копія моделі в приватному
сховищі даних (~640 MB). Усі 639 MB не читаються в Dart-пам’ять одночасно
під час підготовки. Генерація надалі потребує окремої оперативної пам’яті.

Вибір власної моделі, нотатки й інші матеріали зберігаються. Навмисне
видалення Qwen вимикає автоматичне повторне встановлення; повернути її можна
кнопкою «Встановити все». У легкій збірці з вихідного коду ця кнопка завантажує
модель із закріпленого офіційного джерела. Самовільного завантаження 639 MB
через мобільну мережу немає; доступні прогрес, пауза й продовження.

## Цілісність і відновлення

`assets/offline_model/catalog.json` містить точний source revision, розмір,
SHA-256 моделі та контрольні суми карти/довідника. Повна модель пакується у
77 частин до 8 MiB. Незавершена копія має суфікс `.partial`; неповна вбудована
частина переписується при продовженні. Після повного SHA-256 метадані
активуються атомарним записом SQLite. Якщо запис не відбувся, перевірені
байти залишаються для повтору. Пошкоджений файл не позначається як готовий.
Брак місця або мережі показується як незавершене встановлення.

«Перевірити та відновити набір» повторно читає SHA-256 і відновлює відсутній
чи пошкоджений офіційний файл. Власні файли не видаляються. Перевірка файла
та реальна генерація — різні результати; один не підміняє інший.

## Зібрати повний пакет

```bash
flutter pub get --enforce-lockfile
python3 scripts/prepare_offline_payload.py
flutter build apk --release --target-platform android-arm64
python3 scripts/verify_offline_payload.py build/app/outputs/flutter-apk/app-release.apk
```

GitHub Actions готує модель перед Android, iOS і desktop builds. Ваги/частини
не входять у Git; кеш лежить у `build/offline-cache`. Генератор виставляє
`bundle.json` → `included:true` лише після перевіреного розділення. Вихідне
дерево містить легкий варіант `included:false`.

Пакувальник перевіряє каталог, карту, довідник і весь SHA-256 моделі саме
всередині реального APK/IPA/ZIP. Тільки після цього маніфест отримує
`offlineStarter.modelIncluded:true`. Windows/Linux `--self-test-full`
виконує автоматичну підготовку й локальну генерацію в тимчасовому профілі.
Нативні телефонні емуляторні тести перевіряють підготовку та перший запит
без ручного `load`.

Офіційна Apache-2.0 ліцензія Qwen є в `assets/offline_model/QWEN_LICENSE.txt`
і в ліцензіях застосунку. MIT для AMID не замінює сторонні ліцензії.

Нові перевірки/артефакти фіксуються за точним commit/run; попередній зелений
прогін 0.5 не підтверджує 0.6. Фізичні iPhone/Android, BLE/GPS, терміка,
батарея, оновлення встановленої версії, Apple signing і магазини залишаються
окремим прийманням. Непідписаний IPA потребує підписування до інсталяції.

## Надійність запуску iOS-тестів

Для закріпленого Flutter 3.47.6 iOS-тест застосовує вузький backport офіційного
[Flutter #193142](https://github.com/flutter/flutter/pull/193142): запуск очікує
готовності потоку логів симулятора, щоб не пропустити адресу VM Service.
Скрипт перевіряє повний SHA-256 джерела до й після зміни; незнайома версія SDK
відхиляється. Quality перевіряє patch без зміни SDK. iOS використовує окремий
SDK без кешу; рушій, Dart SDK та релізні збірки не змінюються. При оновленні
Flutter цей backport потрібно переглянути або видалити. Результат визначається
справжнім нативним інтеграційним тестом; невдалий запуск не зараховується як успіх.

На iOS холодний запуск worker рушія має обмежений бюджет 2 хвилини замість
бібліотечних 30 секунд: у симуляторі 639 446 688 байтів уже були перевірені,
але worker не встиг ініціалізуватися. Використано вузький адаптер закріпленого
`llamadart 0.20.5`; при оновленні потрібно перевірити його внутрішній імпорт.
Готовність моделі та реальна відповідь залишаються обов’язковими твердженнями
інтеграційного тесту. Довший бюджет сам по собі не означає успішну генерацію.
Ліцензія джерела backport Flutter: [BSD-3-Clause](FLUTTER_TOOL_LICENSE.txt).

## Google Play — наступний незавершений етап

Повний монолітний APK цього релізу призначений для GitHub. Google Play
[обмежує base module до 500 MB стисненого завантаження](https://support.google.com/googleplay/android-developer/answer/9859372).
Поточний великий пакет не позначено готовим до Play. Для збереження установки
всього набору одразу потрібен `install-time` AI pack через
[Play for On-device AI](https://developer.android.com/google/play/on-device-ai):
винести туди частини GGUF, залишити каталог і невеликі матеріали у base,
перевірити доступ до split-активів, SHA-256 та перший запит без мережі після
`bundletool build-apks/install-apks`, потім пройти дозволений internal track.
Ця інтеграція ще не реалізована й не протестована. Підписаний AAB сам по собі
не підтверджує приймання в Play. Apple signing, фізичні пристрої та магазини
також залишаються відкритими критеріями.

У watchOS пункт чекліста є кнопкою на весь рядок із позначкою та читабельним
станом доступності. Ключ збереження `preparation` не змінюється. Тест перевіряє
фактичну зміну стану й збереження після перезапуску, потім відкриває всі 6 карток.
