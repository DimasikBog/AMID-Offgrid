# Web встановлення та офлайн

Вебоновлення після 0.5.0-beta.7. Нативні Dart, Android, Apple та desktop
джерела, ідентифікатори й версії пакетів цього етапу не змінюються.
Опубліковані файли beta.7 залишаються незмінними; нова вебверсія має власний
source commit у `source.json` на GitHub Pages.

## Керування у вебверсії

Над програмою є невелика панель «Офлайн» та «Встановити». Вона доступна
навіть під час запуску Flutter, не накладається на його навігацію та відкриває
підказки для Safari, Android і desktop. Підтримувані браузери можуть показати
власний діалог встановлення. Відмова від нього не означає встановлення.
Запуск в окремому вікні визначається за фактичним display-mode.

«Файли збережені» означає, що worker підтвердив наявність усіх статичних
файлів саме його збірки. Це не перевірка особистих даних, імпортованих пакетів,
мережі, доступного місця чи офлайн-запуску Safari. `navigator.onLine` показано
лише як підказку браузера. Перед поїздкою потрібно реально закрити програму,
відкрити її без мережі й перевірити потрібні матеріали. Backup залишається
обов’язковим для даних, які не можна втратити.

## Надійність підготовки

- Генератор записує шлях, розмір і SHA-256 кожного статичного файлу.
- Під час підготовки worker завантажує файли без HTTP-кешу та перевіряє їхні
  байти перед додаванням. Змішана/неповна версія під час deployment відхиляється.
- Помилка нової версії видаляє лише її неповний кеш; попередня версія та
  персональні browser storage дані не очищуються.
- Відновлення чинної версії завантажує лише відсутні файли. Навіть невдале
  відновлення залишає всі вже збережені файли на місці.
- Навігація root/index/deep link повертає HTML тієї ж встановленої версії,
  що й її runtime. Інші origin, POST і персональні відповіді не кешуються.
- У version digest входить також реалізація worker, тому виправлення лише
  worker не ділить кеш зі старим кодом.
- Окрема адреса `amid-bootstrap.js` дозволяє старому worker beta.7 отримати
  нову конфігурацію Flutter host, а не закривати панель старим full-page bootstrap.

## Оновлення

Новий worker чекає, поки стара версія використовується. Програма не викликає
`skipWaiting` автоматично й не перезавантажується від звичайного controllerchange.
Користувач зберігає нотатку та натискає окреме підтвердження. Worker відмовляє
в активації, якщо бачить інші відкриті вікна AMID у своїй області. Перевірка
вікон не є блокуванням майбутніх відкриттів іншими процесами; резервна копія
та збереження змін залишаються потрібними. Лише вікно, що явно запросило
оновлення, перезавантажується. Сховище нотаток не очищується.

## Перевірка цього етапу

Локально: 13 Python unittest, включно з 11 виконуваними JavaScript-сценаріями
реальних browser scripts у детермінованих Web API fixtures; Node.js 24 без npm.
Перевірено поганий SHA-256, офлайн root/deep links, scope isolation, невдалий
repair без втрати кешу, відновлення лише відсутніх файлів, блокування активації
при іншій вкладці, явне підтвердження, відмову від встановлення, unsupported
browser, стан стартового екрана та повторювану legacy bootstrap міграцію.
Flutter web release із базовим шляхом `/AMID-Offgrid/` скомпільовано.

Fixtures доповнені перевіркою справжнього Chromium, наведеною нижче.
Приймання переходу саме з живої beta.7, встановлена PWA, повне storage eviction та
фізичний iPhone залишаються окремими перевірками.
Нативні пакети й App Store/Google Play не оголошуються новими або готовими
на підставі цього вебоновлення.

Першоджерела:
- https://docs.flutter.dev/platform-integration/web/initialization
- https://docs.flutter.dev/platform-integration/web/embedding-flutter-web
- https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers

## Реальний браузерний CI

Окремий web.yml перевіряє release-build у чистому headless Chromium; те саме
виконується перед Pages deployment. Playwright 1.62.0 встановлюється лише
в тимчасове Python-середовище CI. Програма тестується на localhost у копії
збірки без особистого профілю. Скрипт перевіряє офлайн root/deep-link запуск,
repair, блокування оновлення іншою вкладкою, явне оновлення та відхилення
неправильного hash зі збереженням попередньої версії. Локальне середовище
не дозволило запустити Chromium; тест успішно виконано в GitHub CI:
[run 45455840374](https://github.com/DimasikBog/AMID-Offgrid/actions/runs/45455840374).
Усі чотири фази позначені `PASS actual Chromium`. Також успішні quality
з 112 Flutter-тестами й 12 Python-тестами у
[run 45455840468](https://github.com/DimasikBog/AMID-Offgrid/actions/runs/45455840468).
Точне перевірене джерело: `9a40c648b193b7733a556a69c9c6f5137143301f`.
PR №6 злитий у `cabc5f682527933b0c6c2ae440f6918ab5a04366`, дерево збігається.
Еталон фактичного офлайн-екрана Chrome 390×844 збережено в артефакті
`web-browser-evidence`; панель не перекриває Flutter-навігацію.
Під час першого реального запуску тест виявив видалення loading-вузла
Flutter-рушієм; стартові елементи винесено за межі Flutter host і повторна
перевірка пройшла. Safari та фізичний iPhone залишаються окремими перевірками.

В офлайн-набір не входять приховані службові файли компілятора (зокрема
`.last_build_id`): вони не потрібні для запуску й можуть бути недоступні
через правила хостингу. Діагностика невдалого збереження містить лише
публічний шлях статичного файлу та причину у DOM data-атрибутах; особисті
дані не передаються. Це допомагає відрізнити quota/network/integrity помилку. Фінальне повідомлення
від уже спостереженого worker приймається також після переходу в redundant;
стороннє джерело повідомлень відхиляється. Це перевірено регресійним сценарієм.

## Опубліковане вебоновлення

24 листопада 2026 року [Pages run 45458986644](https://github.com/DimasikBog/AMID-Offgrid/actions/runs/45458986644)
успішно перевірив і опублікував джерело
`5093f93ec5b0917a23d5a9692a2f5e86050acc6d`. Перед deployment пройшли
13 Python-тестів та всі чотири фази справжнього Chromium: перший install
і офлайн root/deep links, repair відсутнього файлу, блокування іншою вкладкою
та явне оновлення зі збереженням даних, відхилення пошкодженої заміни
з офлайн-запуском попередньої версії. `source.json` живого сайту звірено.
Це окремий web deployment; пакети beta.7 не перевидавалися.

У живому cloud Chrome нова панель і Flutter-інтерфейс відкрилися; після
оновлення залишилися сім матеріалів, одна позначка обраного та синтетична
нотатка «Перевірка вебверсії AMID». Діагностика показала
`QuotaExceededError: Quota exceeded.` під час збереження
`canvaskit/canvaskit.wasm`. Через цю квоту повна підготовка нового кешу
в цьому профілі не завершилась; офлайн-запуск саме цього профілю
не підтверджено. Новий неповний кеш відхилено, попередні матеріали збережені.
Дані сайту й попередній кеш вручну не очищувалися, дозволи не змінювалися.
Це окремий результат від успішного Chromium CI; він не доводить ані
несправність Safari, ані готовність встановленої PWA на iPhone.
