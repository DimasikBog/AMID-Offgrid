# Web встановлення та офлайн

Вебоновлення після 0.5.0-beta.7. Нативні Dart, Android, Apple та desktop
джерела, ідентифікатори й версії пакетів цього етапу не змінюються.
Опубліковані файли beta.7 залишаються незмінними; нова вебверсія має власний
source commit у `source.json` на GitHub Pages.

## Керування у вебверсії

Над програмою є невелика панель «Офлайн» та «Встановити». Вона доступна
навіть під час запуску Flutter, не накладається на його навігацію та відкриває
підказки для Safari, Android і desktop. Підтримувані браузери можуть показати
власний діалог встановлення. Відмова від нього не означає встановлення.
Запуск в окремому вікні визначається за фактичним display-mode.

«Файли збережені» означає, що worker підтвердив наявність усіх статичних
файлів саме його збірки. Це не перевірка особистих даних, імпортованих пакетів,
мережі, доступного місця чи офлайн-запуску Safari. `navigator.onLine` показано
лише як підказку браузера. Перед поїздкою потрібно реально закрити програму,
відкрити її без мережі й перевірити потрібні матеріали. Backup залишається
обов’язковим для даних, які не можна втратити.

## Надійність підготовки

- Генератор записує шлях, розмір і SHA-256 кожного статичного файлу.
- Під час підготовки worker завантажує файли без HTTP-кешу та перевіряє їхні
  байти перед додаванням. Змішана/неповна версія під час deployment відхиляється.
- Помилка нової версії видаляє лише її неповний кеш; попередня версія та
  персональні browser storage дані не очищуються.
- Відновлення чинної версії завантажує лише відсутні файли. Навіть невдале
  відновлення залишає всі вже збережені файли на місці.
- Навігація root/index/deep link повертає HTML тієї ж встановленої версії,
  що й її runtime. Інші origin, POST і персональні відповіді не кешуються.
- У version digest входить також реалізація worker, тому виправлення лише
  worker не ділить кеш зі старим кодом.
- Окрема адреса `amid-bootstrap.js` дозволяє старому worker beta.7 отримати
  нову конфігурацію Flutter host, а не закривати панель старим full-page bootstrap.

## Оновлення

Новий worker чекає, поки стара версія використовується. Програма не викликає
`skipWaiting` автоматично й не перезавантажується від звичайного controllerchange.
Користувач зберігає нотатку та натискає окреме підтвердження. Worker відмовляє
в активації, якщо бачить інші відкриті вікна AMID у своїй області. Перевірка
вікон не є блокуванням майбутніх відкриттів іншими процесами; резервна копія
та збереження змін залишаються потрібними. Лише вікно, що явно запросило
оновлення, перезавантажується. Сховище нотаток не очищується.

## Перевірка цього етапу

Локально: 12 Python unittest, включно з 10 виконуваними JavaScript-сценаріями
реальних browser scripts у детермінованих Web API fixtures; Node.js 24 без npm.
Перевірено поганий SHA-256, офлайн root/deep links, scope isolation, невдалий
repair без втрати кешу, відновлення лише відсутніх файлів, блокування активації
при іншій вкладці, явне підтвердження, відмову від встановлення, unsupported
browser, стан стартового екрана та повторювану legacy bootstrap міграцію.
Flutter web release із базовим шляхом `/AMID-Offgrid/` скомпільовано.

Ці fixtures не замінюють перевірку справжнього браузера. Потрібно окремо
записати результат живого deployment, перехід із beta.7, нову вкладку,
встановлену PWA, реальну відмову мережі, storage eviction та фізичний iPhone.
Нативні пакети й App Store/Google Play не оголошуються новими або готовими
на підставі цього вебоновлення.
