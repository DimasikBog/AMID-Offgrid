# Офлайн-карти AMID Offgrid 0.4.2

Вбудована Natural Earth — оглядова карта без вулиць. Для деталізації імпортуй
власний растровий `.mbtiles` через пакети; перевір право користування даними.
Імпорт створює приватну копію й перевіряє SHA-256. Видалення пакета прибирає
цю копію, залишаючи вихідний файл користувача.

## Підтримуваний формат

- MBTiles з `metadata(name, value)` і `tiles(zoom_level, tile_column, tile_row,
  tile_data)` як таблицями або views. Нормалізовані views підтримуються.
- `format`: png, jpg/jpeg або webp; сигнатура зображення має відповідати значенню.
- Рядки тайлів у TMS: південний рядок має індекс 0. Явний `scheme=xyz`
  відхиляється; без scheme використовується TMS.
- `minzoom`/`maxzoom`: цілі значення 0–24. Без них діапазон 0–24.
- `center`: longitude,latitude,zoom або `bounds`: west,south,east,north.
  Без обох центр береться із середини першого наявного тайла.
- Анімовані зображення, векторні PBF і ZIM не підтримуються.

## Ліміти застосунку

| Параметр | Ліміт |
| --- | --- |
| Рядки metadata | 128 |
| Назва / значення metadata в UTF-8 | 128 / 8192 байтів |
| Закодований tile_data | 4 MiB |
| Сторона зображення | 2048 пікселів |
| Загальна кількість пікселів тайла | 1 048 576 |
| Zoom | 0–24 |
| Власні ключі зображень, що утримуються провайдером | 512 |

Це свідомі ліміти AMID, а не загальні вимоги стандарту MBTiles. Наприклад,
1024×1024 дозволено, 2048×2048 — ні. Пакет із потрібними метаданими більшого
розміру доведеться підготувати окремо. Звичайний Flutter ImageCache також має
власні обмеження; 512 ключів не означають гарантовану кількість байтів RAM.

## Що саме перевіряється

Перед активацією перевіряються метадані, координати першого запису й справжнє
декодування одного тайла. Наступні тайли перевіряються під час читання:
дублікати координат, тип і розмір BLOB, сигнатура, роздільність і анімація.
Пошкоджений прочитаний тайл стає прозорим із повідомленням на карті. Відсутній
тайл є нормальною порожньою ділянкою. Помилка відкриття має кнопку повтору.

Це не перевірка кожного запису всього файлу. Необхідні індекси та складність
views впливають на час запитів. SQL-обмеження результатів не обмежують усю
внутрішню роботу SQLite, зокрема обчислення views або перетворення тексту.
Не заявляється захист від довільних ресурсомістких SQLite-файлів.

## Що ще потрібно перевірити на телефонах

1. Імпорт через Android Files та iOS Files, повторне відкриття після перезапуску.
2. Власна карта з відомими координатами й реальною ліцензією: орієнтація,
   масштаб, GPS і відсутність мережі.
3. Плавність, RAM і дисковий простір на великому пакеті; низький вільний простір.
4. Перемикання/видалення карти під час перегляду, згортання й повернення.
5. Пошкоджений пізніший тайл і повтор після недоступного файлу.

Поки ці звіти відсутні, фізичні тести Android/iPhone залишаються **не виконані**.
Синтетичні зображення тестів не є географічними даними або доказом якості карти.
