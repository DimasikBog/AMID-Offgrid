# AMID Azimuth 0.5.0 — перший запуск на твоєму стенді

Мета цього комплекту — перевірити обертання й вибір напрямку за відповідями другого власного LoRa-вузла. Потрібні Arduino Mega, мультиметр і ноутбук. Захищений павербанк із виходом 5 V можна використати як джерело 5 V для моторного драйвера після перевірки його виходу. Характеристики конкретного джерела треба звірити на його етикетці.

Привід цього стенда: 28BYJ-48 саме на 5 V та ULN2003, три NC-перемикачі, легка платформа з окремим підшипником. Для RF-етапу потрібні два сумісні вузли Meshtastic на 868 MHz. Кріплення телефона й павербанка не змінюємо. Обертання обмежене сектором; кабель не повинен намотуватися на вісь.

## 1. Підготуй програму на ASUS / Windows

1. Розпакуй ZIP у звичайну папку. Не запускай програми прямо з архіву.
2. В Arduino IDE відкрий firmware/AMID_Azimuth/AMID_Azimuth.ino, обери Mega 2560 / ATmega2560, свій порт та Upload. Planner.h має лежати поряд. Закрий Serial Monitor після прошивання.
3. За наявності Python 3.10+ та Windows Python launcher запусти SETUP_WINDOWS.cmd. Це створить локальне середовище .venv і встановить залежності; для цього потрібен інтернет.
4. Запусти START_WINDOWS.cmd. Порти лише перелічуються — програма сама не визначає, де Mega, а де радіовузол. Порт Mega можна встановити за зникненням/появою в списку при від’єднанні/під’єднанні її USB.

Діагностика окремою командою після SETUP:

```powershell
.\.venv\Scripts\python.exe diagnose.py --list-ports
.\.venv\Scripts\python.exe diagnose.py --mega-port COM5 --duration 60
```

COM5 — приклад; підстав свій порт. Linux/macOS можуть запускати Python-файли вручну, але ця версія пускових CMD призначена для Windows. Запуск CMD на реальній Windows у цьому середовищі не перевірявся.

## 2. З’єднай сигнали без моторного живлення

Від’єднай USB-живлення моторного драйвера від павербанка. Mega підключи USB-кабелем до ноутбука. NC означає контакт, замкнений із COM у відпущеному стані; NO не використовуємо. Перевір контакти мультиметром при від’єднаному живленні.

| Вихід Mega | Контакт іншої деталі |
|---|---|
| D22 | ULN2003 IN1 |
| D23 | ULN2003 IN2 |
| D24 | ULN2003 IN3 |
| D25 | ULN2003 IN4 |
| GND | ULN2003 GND |
| D26 | NC лівого кінцевика; його COM → Mega GND |
| D27 | NC правого кінцевика; його COM → Mega GND |
| D28 | NC стоп-кнопки; її COM → Mega GND |

П'ятиконтактний моторний штекер вставляється у відповідну розетку ULN2003. Мотор не підключається до GPIO живленням. Уся деталізація ліній — у PIN_TO_PIN.csv.

## 3. Перевір кінцевики до руху

У START_WINDOWS.cmd обери режим 1. Живлення мотора залишається від’єднаним. Діагностика надсилає тільки STOP, PING та STATUS. Вона не надсилає ARM, JOG, SCAN і не підключається до радіовузла. USB-відкриття може перезавантажити Mega.

Порядок: нічого не натиснуто → тільки лівий → відпустити → тільки правий → відпустити → тільки стоп → відпустити. Не рухай платформу приводом на цьому етапі.

| Твоя дія | Очікуваний рядок LEFT / RIGHT / STOP |
|---|---|
| Усе відпущено | 0 / 0 / 0 |
| Натиснуто тільки лівий | 1 / 0 / 0 |
| Натиснуто тільки правий | 0 / 1 / 0 |
| Натиснуто тільки стоп | 0 / 0 / 1 |
| Знову все відпущено | 0 / 0 / 0 |

0 означає, що вхід замкнений на GND; 1 — розімкнений. Обірваний NC-провід також дає 1. Постійний 0 може означати як справний замкнений контакт, так і помилкове замикання: саме тому треба натиснути й відпустити кожен перемикач і звірити відповідний стовпчик.

При натисканні стопа прошивка може показати FAULT — це очікувано; діагностика продовжує читати входи. Результат у diagnostics/*.json позначено OBSERVATIONS_ONLY: програма бачить напругові рівні, але не знає, який фізичний перемикач ти натиснув. Старий HEX v0.2 не передає INPUTS і для цієї перевірки не підходить. Після перевірки закрий діагностику, щоб звільнити порт.

## 4. Подай 5 V на мотор

Перевір мультиметром вихід готового USB-breakout: VCC приблизно 5 V та правильна полярність. Лінії: USB-A павербанка → breakout 5 V → ULN2003 VCC; breakout GND → ULN2003 GND. Спільна GND із Mega потрібна. Не з’єднуй позитивну моторну лінію з +5V Mega, поки Mega живиться від ноутбука. Не використовуй PD/QC-тригер для 9/12 V.

Почни без антени, з порожньою легкою платформою в середині сектору. Запусти режим 2, введи STATUS, потім JOG 16. Після зупинки — JOG -16. Це дуже малий рух; відміть вісь паперовою міткою. Якщо логічний додатний напрямок фізично неправильний, від’єднай моторне живлення, зміни MOTOR_REVERSED у прошивці та проший повторно.

ARM запускає рух пошуку лівого кінцевика. Вводь його лише після правильної реакції на перемикачі та перевірки напрямку. Механічно кінцевик має спрацювати до твердого упору. Після HOMED нуль встановлюється вже з відступом усередину сектору. STOP вимикає котушки й скидає довіру до положення. Під час руху окремо перевір стоп; повернення до роботи — після усунення причини й нового ARM.

NC-стоп у цьому комплекті є входом програми, а не окремим силовим розривом мотора. Для фізичного зняття моторного живлення від’єднується його USB від павербанка. Не тримай пальці в механізмі.

Павербанк може вимикати вихід при малому споживанні. Якщо це стається, мотор може втратити положення без повідомлення програми. Зупинися та повтори ARM після відновлення живлення. Фактична поведінка конкретного павербанка ще не перевірена.

## 5. Перевір радіо без обертання

Під’єднай узгоджені антени 868 MHz до обох радіовузлів до живлення. Установи однакові параметри власного каналу, EU_868, TX enabled та залиш штатні обмеження ефіру. Конкретний RF-роз’єм/пігтейл звіряється з ревізією купленої плати; не вставляй навмання схожі роз’єми. Mega й локальний LoRa-вузол підключаються до різних USB-портів ноутбука; GPIO між ними немає.

У режимі 3 вкажи порт Mega, порт локального вузла та ID другого власного вузла. Спершу введи PROBE. Потрібна реальна відповідь real_radio_ack; без неї не починай SCAN. Перевірка автоматичного ACK PRIVATE_APP на фактичних вузлах залишається відкритим пунктом. Помилка конфігурації або відсутність підтримки ACK не виправляється поворотом антени.

PROBE не запускає мотор. Наступний радіозапит можливий не раніше ніж через 30 секунд; це не обіцянка конкретного airtime чи швидкості. Програма не відключає штатні обмеження ефіру.

## 6. Перший пошук та оцінка результату

Після робочого PROBE та моторних перевірок установи легку антену на платформу з власним підшипником. Перевір запас і вільний вигин коаксіалу в усьому секторі. Мотор не повинен нести вагу антени своїм валом. Вузли й оточення під час порівняння залишаються нерухомими.

ARM → HOMED → SCAN. Дочекайся LOCK_TARGET або NO_SIGNAL. Відкрий report.html у каталозі поточного сеансу. У CSV є медіани RSSI/SNR завершених вікон; два різні ACK — мінімум для вибору, а не гарантія стабільності. При NO_SIGNAL програма не вигадує напрямок.

Повтори пошук кілька разів у незмінних умовах. Запиши, чи повторюється знайдений напрямок, чи є відповіді в обох напрямках і чи не пропускає привід кроків. Сильніший RSSI сам по собі не доводить збільшення дальності або швидкості інтернету. Кути номінальні: для фактичних градусів потрібне механічне калібрування.

Після завершення — STOP і від’єднання моторного живлення. Заповни BENCH_CHECKLIST.csv власними результатами. У наданому шаблоні всі фізичні перевірки NOT_RUN; тут немає вигаданих вимірювань.

Цей стенд ще не є аварійним засобом зв’язку. LoRa передає невеликі пакети між сумісними вузлами; антена не забезпечує глобальне покриття, звичайний браузер або доступ до інтернету без окремого шлюзу. Креслення твоєї 5 GHz Wi-Fi-антени не підходить для цього 868 MHz радіотракту.


Після базових перевірок можна використовувати нове меню 4/5 — панель у браузері. Спершу прочитай PANEL_UA.md. Команди motor/radio та проводка залишаються такими самими.
