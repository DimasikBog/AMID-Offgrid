# Радіочохол — перший фізичний тест із AMID 0.8.1

Мета: перевірити власні два вузли й отримати відтворюваний журнал. Цей файл —
порядок роботи, а не результат вимірювання. У `radio_spec.json` фізичні перевірки
залишаються `not_run`. Сам експорт із додатка не підтверджує калібрування,
дальність, безпеку корпуса або глобальне покриття.

## Підготовка на столі

1. Використати два сумісні T3-S3/SX1262 868 MHz із заводськими антенами.
   Під’єднати антени перед увімкненням живлення. Власний диполь спочатку налаштувати VNA за
   [основною інструкцією](README_UA.md); складати його лише при вимкненому радіо.
2. Налаштувати обидва вузли за основною інструкцією: точна прошивка, EU868,
   однаковий preset, власний випадковий 32-байтовий ключ, MQTT uplink вимкнений,
   штатні обмеження ефіру. Закрити інший BLE-клієнт.
3. На телефонах встановити відповідний нативний AMID. iPhone потребує належного
   підписування; вебверсія дозволяє переглядати звіти, але не підключає модуль.
4. Відкрити «Зв’язок → Радіочохол LoRa», знайти власний модуль, підтвердити PIN,
   дочекатися конфігурації й вибрати налаштований канал.
5. Перевірити заряд, кабелі, відсутність тиску корпуса на телефон/камери/порти.
   Визначити зрозумілий спосіб спілкування між людьми для звірки результатів.

## Один сеанс

1. Натиснути «Почати тест». Ця дія не надсилає пакетів і не вмикає GPS.
2. Вказати адресу другого власного вузла. Вручну надіслати пронумеровані короткі
   повідомлення, наприклад `AMID TEST 01`, `AMID TEST 02`. Між повідомленнями
   додаток вимагає щонайменше 10 секунд; прошивка може додатково обмежити ефір.
   Автоматичної серії передач немає.
3. Для кожного повідомлення звірити показаний стан та його появу на другому
   телефоні. «Прийнято чергою» ще не доставка. ACK протоколу не є прочитанням
   людиною або незалежним доказом авторства.
4. Для зворотного напрямку почати окремий тест на іншому телефоні. Для розсилки
   почати окремий сеанс: розсилка не дає ACK кожного адресата й не входить у
   знаменник частки одноадресних підтверджень.
5. Натиснути «Завершити й зберегти». Дочекатися появи звіту у списку. Відкрити
   його та зберегти JSON або скопіювати JSON явною кнопкою.

До звіту входять лише спроби, розпочаті після «Почати тест». Уже очікувані
передавання попереднього сеансу не додаються. При виході з екрана, згортанні,
від’єднанні або зміні каналу/конфігурації тест завершується. Нерозв’язані спроби
позначаються перерваними; відсутність ACK після тайм-ауту — окремий стан.

Ліміти — 100 спроб або 60 хвилин. Після 100 спроб заверши звіт; наступна ручна
відправка завершить заповнений тест і сама вже не ввійде до нього. Зберігаються
останні 20 звітів, старіші замінюються новими. Експортуй потрібні перед довгою
серією вимірювань. При помилці запису звіт залишається в пам’яті з кнопкою
повтору; новий тест заблоковано до успішного збереження. Не закривай застосунок,
поки не вирішиш помилку. Активний незавершений сеанс не переживає аварійного
завершення процесу або розряджання телефона.

## Як читати звіт

| Поле | Значення й обмеження |
| --- | --- |
| `unicast` | Одноадресні спроби, ACK, відмови, тайм-аути й переривання |
| `broadcast` | Окремі підсумки розсилки; `acknowledged` завжди 0 |
| `ackMs` | Затримка від спроби запису через BLE до відповідного ACK у додатку; монотонний годинник |
| `rssiDbm`, `snrDb` | Кількість, мінімум, максимум і середнє для нових текстів та відповідей на спроби тесту без MQTT |
| `receivedTexts` | Нові тексти вибраного каналу без MQTT; повтори не додаються |
| `processingErrors` | Помилки декодування чи обробки у вхідній черзі; це не лічильник втрат в ефірі |
| `reason` | Ручне завершення, від’єднання, зміна конфігурації, час або місткість |
| `verification` | Завжди `unverified`; імпорт із backup не змінює довіру до спостережень |

Частка ACK показується як підтверджені / усі одноадресні спроби. Відмови й
перервані спроби залишаються у знаменнику. Це не чистий packet-loss радіолінії:
впливають BLE, черга, стан іншого вузла та зворотний шлях ACK. Відсутній сигнал
позначається як «немає вимірювань», а не 0 dBm.

RSSI/SNR описують останній прийнятий радіострибок. Через ретранслятор вони не
вимірюють лінію безпосередньо між двома телефонами. Додаток не обчислює відстань
або гарантоване покриття з потужності сигналу й не знає фактичний маршрут усіх
пакетів. Затримка ACK містить BLE, чергу, маршрут і відповідь; це не час польоту
радіохвилі. Ознаці MQTT та метаданим AMID довіряє як даним власної прошивки.

## Виїзне порівняння

Після успішного столового тесту перевірити окремо відкриту місцевість, ліс і
забудову. Для кожної точки створити окремий звіт. Відстань визначати незалежно
й записувати вручну, не виводити з RSSI. Зберігати однакові preset, антени,
положення телефона, напрямок і число спроб; змінювати один чинник за раз.

До окремої особистої нотатки записати тип антени, висоту/орієнтацію, умови,
фактичну відстань, стан акумулятора, наявність інших вузлів і ідентифікатор JSON.
Не підставляти ці умови в уже створений звіт як автоматично виміряні.

Перед оголошенням результату повторити перевірку у зворотному напрямку й за
іншого розташування. Спочатку порівнювати заводські антени; власний диполь —
лише після окремого налаштування й повторного тесту з телефоном та рукою.

## Приватність і збереження

JSON містить агреговані лічильники, час створення, тривалість, версії AMID/
прошивки й регіон. Текстів, PSK, BLE-ідентифікаторів, адрес вузлів і GPS немає.
Копіювання/експорт запускається власником; автоматичного надсилання звітів немає.
Звіти входять у звичайну резервну копію. Для її шифрування використовувати
наявний парольний експорт. Старі backup без `radioReports` читаються; конфлікт
звіту з тим самим ID відхиляє відновлення до зміни локальних даних.
